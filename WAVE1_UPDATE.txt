Updates in this Wave


What We Designed 🎨

We architected a privacy-first B2B invoice system on Aleo with:

  - Dual-Record Model: Each invoice creates two private records (seller + buyer) to maintain independent ownership while ensuring data consistency

  - Two-Step Payment Flow: Separates credit transfer (credits.aleo) from invoice status update (zk_invoice.aleo) for reliability

  - 4-Layer Architecture: View → Controller → Service → Model separation for clean, maintainable code

  - Audit Key System: Selective disclosure mechanism for compliance without compromising overall privacy


What We Built 🔧

Smart Contract (zk_invoice.aleo)
  - create_invoice() - Generate encrypted invoice records for both parties
  - mark_as_paid() - Update status with ZK proof of payment
  - cancel_invoice() - Seller-initiated cancellation
  - verify_invoice() / verify_payment() - On-chain verification

Frontend Application
  - Dashboard with invoice statistics
  - Invoice creation form with real-time validation
  - Invoice list with role-based filtering (as seller / as buyer)
  - Payment flow with transaction status polling
  - Receipt viewer for payment proofs
  - Audit key generator for compliance

Infrastructure
  - Wallet integration (Leo Wallet & Puzzle Wallet)
  - IndexedDB persistence with encryption
  - Blockchain sync service with polling
  - Comprehensive error handling
